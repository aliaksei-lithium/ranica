## 1. The inspiration

The reference photo is a personal one-copy daily newspaper ("Утренний Мардан", issue 2,
Astana). What makes it work, and what we keep:

| Element on the page | Why it works | Ranica equivalent |
|---|---|---|
| Huge date number + month, weekday, year | Instantly readable at arm's length, feels like a real paper | Masthead, same idea |
| Edition name, issue number, "print run: one copy" | Personal, playful | "Issue №N", "Print run: 1 copy, <city>" |
| Sunrise / sunset / day length / countdown ("until 30 Sec…") | Dense "almanac" line, zero words wasted | Sun line + user countdowns |
| Weather: big number, then plain-language sentence, then a one-line advice | Number for the glance, text for the decision ("hat won't hurt") | Same, advice generated by rules + LLM |
| "Things for today" with checkboxes and a grey sub-line per task (context: "DocuSign sent 2nd reminder") | Calendar + tasks merged, with the *why* under each item | Agenda + tasks block with context lines from the LLM |
| News grouped by rubric (AI, Kazakhstan…), each item 1–2 lines + source | Scannable, sourced | News rubrics from RSS/Telegram, source tag on each item |
| Boxed "Idea of the day" with a stat | Personal insight, visually separated | "Insight" box from user context |
| Comic strip of the day | Fun, personal | Out of scope for v1; placeholder slot for a later image feature |

Conclusion: the format is a **dense, monochrome, A4, two-column broadsheet**, not a dashboard.
Everything should fit on one page; a second page is optional and only for "long reads".

## 3. Data sources

### 3.1 Calendar
- **ICS URL** (Google "secret address in iCal format", Outlook, iCloud, Nextcloud): zero
  OAuth, works for any provider, read-only. Parse with `ical4j` (JVM). **Use this for v1.**
- **Google Calendar API (OAuth)**: richer (colors, attendees, conference links). Caveat for a
  hobby project: an OAuth app in *Testing* mode has refresh tokens that expire after 7 days;
  publishing to *Production* with calendar scopes needs Google verification. Plan it for the
  multi-user phase only.
  ([unipile](https://www.unipile.com/google-oauth-refresh-token/), [sailjada](https://tech.sailjada.com/posts/2026-05-06-1856.html))
- **CalDAV** (generic): optional later.

### 3.2 Tasks
- Google Tasks API, Todoist REST API, or a plain Markdown/Obsidian file in a Git/Drive folder.
  v1: a simple "tasks.md" the user edits + optional Todoist. Tasks also come from the LLM
  ("your DocuSign is unsigned for 3 days") when email is connected later.

### 3.3 Weather
- **Open-Meteo**: free for non-commercial use, no API key, ~10 000 requests/day fair use.
  Daily: `sunrise`, `sunset`, `daylight_duration`, `apparent_temperature_max/min`,
  `precipitation_probability_max`, `wind_speed_10m_max`, `weather_code`, `uv_index_max`,
  `sunshine_duration`. Hourly: `temperature_2m`, `apparent_temperature`,
  `precipitation_probability`, `wind_speed_10m`, `weather_code`. One request per city per day.
  **Verified live**: `GET api.open-meteo.com/v1/forecast?latitude=52.52&longitude=13.41&daily=…&timezone=Europe/Berlin`
  returned all of the above; `daylight_duration` is in seconds (34 020 s = 9 h 27 min for Berlin today).
- **Bright Sky** (DWD, Germany only): no key, hourly + MOSMIX forecasts; nice second source
  for users in Germany. ([brightsky.dev](https://brightsky.dev/))
- The "feels colder than the numbers, take a hat" line is **rules + LLM**: rules decide the
  facts (apparent temp < 0 and temp > 0 → "feels colder"), LLM phrases it.

### 3.4 News from newspapers (RSS)
- RSS is still the simplest reliable channel. Parse with `Rome` (JVM) or `feedparser` (Python).
- **Verified live** (HTTP 200, item count in brackets):
  - Tagesschau `https://www.tagesschau.de/index~rss2.xml` [69], rubric pattern
    `https://www.tagesschau.de/wirtschaft/index~rss2.xml` [19]
  - Deutschlandfunk `https://www.deutschlandfunk.de/nachrichten-100.rss` [38]
  - Deutsche Welle (German) `https://rss.dw.com/rdf/rss-de-all` [88]
  - Heise `https://www.heise.de/rss/heise-atom.xml` [157] (Atom)
  - BBC World `https://feeds.bbci.co.uk/news/world/rss.xml` [23]
  - Google News query `https://news.google.com/rss/search?q=<query>&hl=en-US&gl=US&ceid=US:en`
    (returns a feed; results depend on the query)
- Also candidates: Hacker News, The Verge, DW "Langsam gesprochene Nachrichten" (podcast feed,
  good for the German block), Nachrichtenleicht (DLF, easy German).
- Google News RSS search gives "news about <topic>" for hobby rubrics with zero scraping.
- Fetch **once per source per interval, shared by all users** (a feed is not per-user data).
- De-duplicate by canonical URL and by normalized title (same story from several outlets).

### 3.5 Telegram channels
Three ways to read a *public* channel ([comparison](https://dev.to/starnikovoleg/three-ways-to-read-a-public-telegram-channel-and-what-each-one-costs-17h)):

| Method | Needs | Pros | Cons |
|---|---|---|---|
| `https://t.me/s/<channel>` HTML preview | nothing | No account, full text, dates, views, photos; paging with `?before=<id>` | Public channels only, no comments, Telegram can change markup, must rate-limit |
| **RSSHub** `/telegram/channel/<name>` | self-hosted RSSHub | Wraps the same preview as RSS | Extra service; public instance unreliable |
| **MTProto** (Telethon/TDLib) with a user session | api_id/hash + phone, session file | Full history, private channels you are in, reactions | Session file = your account; ban risk if abused |
| Bot API | bot must be channel admin | official | Useless for channels you don't own |

**Verified live**: `curl https://t.me/s/tagesschau` returned 93 KB of HTML with 20 posts; each
post has `data-post="<channel>/<id>"`, `.tgme_widget_message_text` and `<time datetime=…>`,
so parsing needs ~20 lines of jsoup. Latest post was 3 hours old at fetch time.

Decision: **v1 = t.me/s scraping with jsoup**, cached per channel (not per user), polite rate
(1 req / channel / 15 min). MTProto later as an optional "bring your own session" sidecar for
private channels.

### 3.6 German words (spaced repetition)
- **FSRS-6** is the current open algorithm (used by Anki). JVM: [FsrsKt](https://github.com/TheRockYT/FsrsKt)
  (Kotlin Multiplatform, Maven Central `one.felsen.fsrskt:fsrskt`, README verified live).
  Python: `py-fsrs`.
  ([open-spaced-repetition](https://github.com/open-spaced-repetition))
- Paper has no "Again/Good" buttons. Two modes:
  1. *Paper mode*: a card printed today is treated as reviewed "Good" unless the user marks it
     "Again" on the web page before midnight (or scans a QR to the review page).
  2. *Web mode*: normal 4-button grading on the web edition.
- Import: CSV / Anki export (`.txt` tab-separated) / a Google Sheet. The LLM can also pull
  **new words from today's German news items** and add them as suggested cards.

### 3.7 AI insight ("based on user-predefined context")
- One LLM call per edition with: user context (Markdown, e.g. goals, projects, people, habits),
  today's events, tasks, weather facts, candidate news items (title + 2 lines + source + time),
  due vocabulary, hobby topics. Output is a **strict JSON schema** (structured outputs), never
  free text, so the renderer stays deterministic.
- The LLM **rewrites and ranks only supplied items**; it never invents news. Every news item
  keeps its URL (rendered as a tiny source tag, optionally a QR code).
- Model and cost (Anthropic API, first-party prices, Nov 2026):
  - `claude-opus-5-5`: $4 / $20 per MTok — editor-in-chief call (quality of selection and
    writing matters, it is one call per day).
  - `claude-haiku-5-5`: $0.10 / $0.50 per MTok — optional pre-filter when there are hundreds
    of candidate items.
  - Estimate per edition: ~20k input + ~3k output tokens → **≈ $0.14/day with Opus 5.5**, ≈
    $0.004 with Haiku 5.5. With prompt caching of the stable system prompt + user context the
    input part gets cheaper. For a public app: ~$4/user/month at Opus quality, which sets the
    price floor of a paid tier.
  - Thinking is adaptive by default; use `output_config.effort: "medium"` for this job.
    Include the server-side `fallbacks: "default"` option so a safety refusal still returns an
    edition.

### 3.8 Hobby facts, sport reminders, "on this day"
- Hobby facts: Wikipedia REST "On this day" (`/feed/onthisday/events/MM/DD`) and
  Google News RSS per hobby keyword; the LLM picks one and writes 2 lines.
- Sport: rules on calendar + user profile ("gym Mon/Wed/Fri", "run if no rain and > 5 °C") →
  one reminder line with the weather check already applied.

## 4. Rendering: HTML → paper / PDF / image

| Engine | Pros | Cons |
|---|---|---|
| **Chromium via Cloudflare Browser Run** (`@cloudflare/puppeteer` binding or REST `/pdf`, `/screenshot`) | Full modern CSS (grid, flex, `@page`, fonts), same HTML for web and print, PNG for e-ink; nothing to install; `page.pdf({format:'A4', printBackground:true, preferCSSPageSize:true})` | 10 browser-minutes/day on Free; one new browser per 20 s; keep one session per edition and do measure → trim → pdf → png inside it |
| Chromium via Playwright (local) | Same engine, unlimited, good for template development and golden tests on a laptop/CI | Not available inside Workers |
| WeasyPrint (Python) | No browser, good `@page` support | No flexbox/grid (morning-briefing had to use tables), Python only |
| Typst | Beautiful typography | Separate markup; cannot reuse the web HTML |
| Paged.js | CSS paged media polyfill | Still needs Chromium |

Decision: **one HTML template, print CSS (`@page A4`, CSS grid, 2 columns), rendered by
headless Chromium (Browser Run in production, Playwright locally)**. The web home page *is*
the template; PDF and PNG are screenshots of it. Fit-to-page runs **inside one browser session**:
load HTML → `page.evaluate` measures overflow and removes the lowest-priority blocks → `page.pdf`
→ `page.screenshot`. 1-bit dithering for e-ink is done in the page with a canvas, so it costs
browser time, not the Worker's 10 ms CPU.

Typography: a classic serif for headlines (Playfair Display / Old Standard TT), a readable
serif for body (PT Serif / Source Serif), a grotesque for numbers (Inter). All under OFL so the
fonts can be bundled. Monochrome by design: it prints on any printer and looks right on e-ink.

## 5. Delivery channels

| Channel | How | Notes |
|---|---|---|
| Browser home page | `GET /today` → 302 to latest edition HTML; `GET /u/<token>/today` for unauthenticated kiosk/e-ink use | Auto-refresh meta tag; archive under `/editions/YYYY-MM-DD` |
| Print | user downloads PDF; or server sends to printer via IPP/CUPS (`lp`) when self-hosted; or email-to-print (HP/Brother/Epson have email printers) | IPP from the cloud is hard; email-to-print is the portable path |
| Kindle | Send-to-Kindle **email** with a PDF attachment. **Verified live on amazon.com/sendtokindle/email**: supported types PDF, DOC, DOCX, TXT, RTF, HTM, HTML, PNG, GIF, JPG, JPEG, BMP, EPUB; only *approved* sender addresses are accepted; no subject line needed. Limit of 25 files / 50 MB per mail is from third-party pages (*verify*). Kindle Scribe/Paperwhite: a PDF sized to the screen (e.g. 6.8" ≈ 1236×1648 px) keeps the newspaper look; for reflow send EPUB. | Alternative: jailbroken Kindle as a dashboard (TRMNL guide) polling the PNG URL |
| E-ink (TRMNL, Inkplate, Kindle-dash) | `GET /u/<token>/today.png` 1-bit PNG at the device resolution | Free by-product of Chromium screenshots |
| Email | HTML mail with PDF attached, via any SMTP / Resend / Postmark | Also the vehicle for Kindle |
| Thermal receipt printer | ESC/POS raster from the PNG (58/80 mm) | Phase 4, dailytimes already solved it |

## 6. Hosting: Cloudflare free tier (decision)

Everything runs on one Cloudflare account on the Workers Free plan. Official limits, read from
developers.cloudflare.com on 2026-11-03 (**verified live** unless marked):

| Product | Free limit | What it means for Ranica |
|---|---|---|
| Workers | 100 000 requests/day; **10 ms CPU per request and per Cron Trigger**; 50 subrequests per request; 128 MB; 5 Cron Triggers per account | I/O wait is free, CPU is not. Parsing many feeds in one invocation will hit 10 ms. Split work into Workflow steps. |
| Workflows | available on Free; **10 ms CPU per step**; 1 024 steps per instance; 100 MB state; 3-day retention; ~3 000 steps/day (*third-party figure*) | One Workflow instance per edition; one step per source/LLM/render/delivery gives each its own 10 ms budget plus retries. |
| Queues | 10 000 operations/day on Free | Enough for delivery fan-out; Workflows already cover most of it. |
| D1 (SQLite) | 5 M rows read/day; **100 000 rows written/day**; 5 GB | Main database. Dedupe items before insert; refresh shared sources at most hourly. |
| KV | 100 000 reads/day; **1 000 writes/day**; 1 GB | Too few writes for sessions or caches. Use D1 and R2 instead. |
| R2 | 10 GB; 1 M class A ops/month; 10 M class B ops/month; **free egress** | HTML/PDF/PNG artifacts, served through the Worker. |
| Durable Objects | SQLite-backed only; 100 000 requests/day; 13 000 GB-s/day; 5 GB | Optional per-user alarm scheduler; not needed in v1. |
| Browser Run (Browser Rendering) | **10 minutes of browser time/day**; 3 concurrent browsers; 1 new browser every 20 s; REST API 6 requests/min (*third-party figure*) | PDF + PNG rendering. One edition ≈ 5–8 s of browser time → roughly 80–100 editions/day on Free. |
| Workers AI | 10 000 neurons/day | Free LLM fallback (Llama 3.x 70B ≈ 1 000–1 500 neurons per edition → ~7 editions/day). |
| AI Gateway | core features free (analytics, caching, rate limiting) | Route Anthropic calls through it for logs and spend control. |
| Email Service | **outbound sending not available on Free** (only to verified addresses in your own account); inbound routing unlimited | For your own Kindle/email you could verify your addresses and send free; for other users use Resend. |
| Static assets | unlimited free requests | CSS, fonts, settings UI. |
| Cloudflare Access (Zero Trust) | free up to 50 users, one-time PIN by email or Google login (*verify*) | Login without writing auth code or sending mail yourself. |

Third-party email for arbitrary recipients: **Resend** free tier ≈ 3 000 emails/month, 100/day,
HTTP API with attachments (*verify on resend.com/pricing*). A custom domain (~€10/year) is needed
for a sending address that Amazon's approved-sender list can accept.

Language: Workers run JavaScript/TypeScript (also Python via Pyodide, and WASM). There is no JVM,
so the implementation language is **TypeScript**. Kotlin/JS can target Workers but the toolchain
is immature; Python Workers have a limited package set and slower cold starts.

Capacity on Free for a public app: the binding constraints are browser minutes (~100 editions/day)
and Resend (100 mails/day). Above that, Workers Paid is $5/month and lifts most caps.

## 7. Legal / etiquette notes
- RSS and `t.me/s` are public, but show the source and link; keep summaries short (2 lines),
  never republish full articles.
- Open-Meteo: non-commercial free tier; a paid plan is needed if Ranica ever charges money.
- GDPR for a public app: store only what the page needs, export + delete in one click
  (dailytimes does this; copy it).
